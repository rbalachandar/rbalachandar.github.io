Proef is an open-source framework where AI agents propose hypotheses, run experiments and judge the results against criteria fixed before the experiment ran. Every claim carries its uncertainty, every decision is on a tamper-evident record, and a person stays in control of what reaches the lab.

WHY PROEFAn agent that can be graded, not just trusted

Most agent demos show a model that sounds right. Proef is built around the opposite question: when the model is wrong, thin on evidence or manipulated, what stops it from reaching the lab or a published claim?

Models propose and advise. Code decides and enforces. A person approves what reaches the lab.
A model never writes a verdict, never approves its own submission and never moves a gate.

Pre-registered, falsifiable
Every hypothesis records its predicted value and a refuted-if clause before any data exists. Verdicts are judged against criteria registered beforehand.
Honest about uncertainty
A confidence interval that straddles the gate abstains. It is never rounded into a pass or a fail, and an abstention is graded down, not counted as a win.
A person stays in control
The only path from an agent to a lab is a gateway with a policy engine the agent cannot modify, an operator halt it cannot lift, budgets, and a plan a person reviews first.
Auditable end to end
Every decision, call, result and verdict lands on a hash-chained ledger. A campaign can be replayed from it with no model and no network, and an audit checks its rules over the record.

HOW IT WORKSOne campaign, from question to verdict

Given a research problem and its constraints, agents propose a portfolio of hypotheses, select the ones worth testing, design experiments, run them on simulated or real equipment, and deliver verdicts as the results arrive.

THE WORKBENCHWhere a scientist actually works

A web workbench sits on top of the engine. Programs hold a pre-registered gate and many campaigns; decisions wait for a person; a plate run by hand is judged against the gate registered beforehand.

Programs and campaigns
A program is the goal and its gate. Campaigns run against it, in parallel, sharing one pool of lab runs. A model can split an objective into sub-problems that you review first.
Decisions in one place
Pending approvals and abstentions to follow up, accept or drop, filterable or grouped by program, each recorded under a name.
Bring your own plate
proef read results.csv turns an instrument export into fitted curves, intervals and QC, with no model involved.

TRUST MECHANISMSGuarantees that live in code, not in a prompt

MechanismWhat it guarantees
Uncertainty vetoes certaintyA 95% interval that straddles the gate abstains, on any metric.
Molecular safety gateVersioned toxicophore rules; hard classes always refuse; electrophilic warheads pass only with declared covalent intent. Regulated pathogens and toxins are refused and the refusal is recorded.
Execution governanceAn operator halt the agent cannot lift, an autonomous / human-approved / never authorization matrix, budgets that cap what a campaign may consume.
Tiered trustDeterministic rules hold the floor. A model may add a flag or demand human review; it can never clear a refusal.
Provenance physicsThe hash chain is enforced by the database and recomputed on read; Merkle anchoring lets anyone check the record was not edited.
Grounded, not assertedItems a model cites from the literature must trace to retrieved results. Prior predictions are labelled priors, never evidence.
Input trust boundaryJunk or adversarial instrument files degrade to "unreadable, no verdicts changed"; injection-shaped sample names cannot reach the gate as instructions.

EVIDENCEGraded by its own harness, tested on real data

proef eval runs 25 scored tasks against seeded ground truth: deterministic, offline, and run in CI. The latest run: mean 0.947, all passing. Scores below 1.0 are kept as reported.

STATUSWhat is and is not proven

  • Most results here come from simulated labs and replayed real data. Simulated numbers are always labelled as such.
  • Nothing is hardware-validated yet: the Opentrons path is contract-tested against a simulated robot, and the MCP instrument path was exercised live against two third-party servers only.
  • With a real model, the framework was validated end to end (tool use, grounding, replay, blinding). Whether grounding improves hypothesis quality has not been evaluated.
  • Sandboxing is opt-in. Docker isolation is verified in CI; analysis fits still run in-process.
  • The live plan is on GitHub in docs/ROADMAP.md.

GET STARTEDTry it in two minutes

From a checkout, no lab and no API key needed. The demo and tests run offline on a simulated lab.

git clone https://github.com/rbalachandar/proef.git
cd proef
make install        # python package + web deps into ./.venv
.venv/bin/python -m proef.cli demo     # abstain-and-refute cascade (simulated)
make run            # workbench on http://localhost:8000
# with .venv/bin on your PATH (or prefix each command with .venv/bin/)
proef read results.csv                       # analyze an instrument export
proef campaign auto --template dose-response-screen \
      --field compounds=C1,C2,C3 --autonomy act --yes
proef prove <branch> --html out.html     # tamper-evident report
proef eval                                    # the graded suite

Bring a model with PROEF_LLM_PRESET / PROEF_LLM_MODEL (any OpenAI-compatible endpoint or Anthropic). Full guide: QUICKSTART.
